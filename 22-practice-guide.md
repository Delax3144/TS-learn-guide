## Повторить проверку типов

Открой терминал в `F:\TS learn`. Если TypeScript уже доступен:

```powershell
tsc -p tsconfig.json
```

Если команда не найдена, при установленном Node.js с npm можно разово запустить
ту же версию, которой проверен этот конспект:

```powershell
npx --yes --package typescript@7.0.2 tsc -p tsconfig.json
```

Первый запуск может скачать пакет в кэш npm; зависимости в папку конспекта не добавляются.
Проверка без сообщений и с кодом завершения 0 означает отсутствие ошибок типов.
`noEmit` запрещает создавать JS при этой команде. Это проверка, а не выполнение.
Используй `-p tsconfig.json`: вызов `tsc отдельный-файл.ts` не применяет настройки проекта.

В конфигурации включены `strict` и `noUncheckedIndexedAccess`: чтение произвольного
элемента массива может дать undefined. `exactOptionalPropertyTypes` не включён,
поэтому некоторые необязательные поля допускают явное undefined — пример в теме 16.
`target: ES2020` позволяет использовать bigint. Архивные копии имеют расширение `.txt`.

## Запустить пример и увидеть результат

Самый простой отдельный эксперимент — скопировать один файл в
[TypeScript Playground](https://www.typescriptlang.org/play/), включить Strict
и noUncheckedIndexedAccess в TS Config, добавить `console.log` и нажать Run.

Можно запустить один пример локально: в терминале из папки проекта выполни
команды ниже. Они создадут только папку `.practice-output` с JavaScript.

```powershell
npx --yes --package typescript@7.0.2 tsc -p tsconfig.json --noEmit false --module commonjs --outDir .practice-output
node .practice-output/18-function-overloads.js
```

Если файл ничего не выводит, это нормально: вычисленные const сами не печатаются.
Для эксперимента добавь в учебную копию `console.log(parseInput('hello world'))`
и повтори компиляцию. `tsconfig` проверяет только `.ts` в корне: если добавишь
свои подпапки с кодом, включи их в `include` или создай отдельный проект.

## Небольшой проект: список задач

Начни без сервера и библиотек, с массива объектов. Потом можно добавить интерфейс.

1. Опиши Todo с id, title и status: 'todo' | 'done'. Создай 2–3 задачи.
2. Напиши добавление, поиск по id, смену статуса и фильтрацию. Для поиска выбери
   результат Todo | undefined и обработай отсутствие в вызывающем коде.
3. Отдели данные для создания через Omit<Todo, 'id'>. Для редактирования
   используй Partial<Pick<Todo, 'title' | 'status'>>. Объясни запрет смены id.
4. Опиши подписи статусов через Record<Todo['status'], string>.
5. Добавь состояние loading/success/error как discriminated union.
6. Позже попробуй импорт одной задачи из JSON: unknown, проверка полей,
   проверка литерала status, понятное сообщение об ошибке.

Критерий готовности этапа: можешь объяснить вход и результат каждой функции,
нет случайных as/any/!, проверены пустой список, неизвестный id и неверные данные.
Не добавляй infer или перегрузки, если текущий этап спокойно решается проще.

## Что осталось в текущих упражнениях

- 1–3, 6–9: рабочие решения, включая исправленные форматирование и последний индекс.
- 4: ApiResponse описан правильно; handleResponse только читает свойства.
  Сам выбери полезное действие: вернуть результат либо вывести данные/сообщение.
- 5: loading возвращает undefined. Если ожидаешь текст для каждого состояния,
  добавь сообщение о загрузке и результат `: string`.
