# Советы после курса

## Что сохранить со слайда

1. Начни с базы, не зацикливайся на сложных типах.
2. Закрепляй знания в небольших собственных проектах.
3. Меньше изолированных головоломок, больше функций с понятным назначением.
4. В учебном проекте временный обход сложной ошибки допустим, но не превращай
   `any`, `@ts-ignore` и `as` в привычный способ «починить» код.

Последний совет на слайде специально ограничен пет-проектами. Практический смысл:
не останавливать всё обучение из-за одной сложной типизации, но вернуться к ней.
Это не делает обход безопасным. В рабочем коде тоже бывают обоснованные assertions,
но основание должно быть конкретным: какая гарантия есть и почему TS её не видит.

## Если ошибка мешает двигаться

1. Прочитай ожидаемый и фактический типы. Найди первое несовпадающее поле.
2. Наведи курсор на значение: возможно, оно уже `string | undefined`, а не `string`.
3. Проверь данные и логику: объект неполный, забыли return, число осталось строкой?
4. Упрости пример до одной функции. Выбери проверку, корректный тип или преобразование.
5. Если пока обходишь проблему, оставь рядом TODO с причиной и условием удаления.
   Ограничь обход одной точкой; не делай весь результат запроса `any`.
6. Вернись к TODO после работающего маленького этапа, прежде чем копировать код дальше.

`@ts-ignore` подавляет ошибку следующей строки. `@ts-expect-error` тоже подавляет её,
но сам сообщает об ошибке, когда подавлять уже нечего. Он полезен для проверок
ожидаемых ошибок типов и временных обходов с объяснением. Ни один комментарий
не исправляет поведение JavaScript. [Официальное пояснение](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-3-9.html#ts-expect-error-comments).

`as const` не нужно считать плохим только из-за слова as. Он сохраняет литералы.
`satisfies` проверяет соответствие типу при компиляции. Внешние данные требуют
проверок значений — см. [assertions](09-type-assertions-and-satisfies.ts) и
[assertion functions](17-assertion-functions.ts).

## Что нужно уметь, а что можно подсмотреть

| Уровень | Что закреплять |
|---|---|
| Писать самостоятельно | Типы аргументов и результата, объекты, union, narrowing, обработка undefined |
| Уверенно применять | Generic для массива/контейнера, состояния запроса, Partial/Pick/Omit/Record |
| Понимать при чтении | keyof, typeof в типах, T[K], is, asserts, перегрузки, кортежи |
| Искать по необходимости | Сложные mapped/conditional types, infer, особенности const enum |

Не требуется помнить определения всех утилит. Нужно узнавать задачу и выбирать
подходящий инструмент. Если готовая утилита решает задачу, используй её.

## Как повторять

Выбери одну тему и потрать 15–25 минут:

1. Прочитай один пример, предскажи тип и результат до запуска.
2. Закрой пример и напиши похожую функцию с другими данными.
3. Проверь обычный случай и крайний: пустой массив, 0, false, null, неверный объект.
4. Объясни вслух вход, результат и гарантию каждой проверки.
5. На следующий день повтори без копирования; позднее примени в своём проекте.

Отсутствие ошибок компилятора — только часть проверки. `getLast` с индексом
`arr.length` компилировался, но возвращал undefined. Всегда смотри на результат.

## Куда двигаться после видео

Возьми один небольшой проект из [руководства по практике](22-practice-guide.md).
Сначала сделай данные и функции, затем интерфейс. Новую сложную конструкцию
добавляй, когда можешь объяснить, какую конкретную проблему она решает.

Если запутался, открой [шпаргалку](21-quick-reference.md), затем файл нужной темы.
Архив хранит старые варианты с ошибками — используй для сравнения, не для заучивания.
