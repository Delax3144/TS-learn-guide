# Промежуточные итоги

Это сохранённая остановка в середине курса. Видео уже завершено; теперь используй
эти вопросы для повторения, а дальнейший маршрут — в [руководстве](22-practice-guide.md).

## Что означает слайд

**Статическая типизация:** TypeScript проверяет код до выполнения. После
компиляции аннотации типов исчезают; ответы сервера сами по себе не проверяются.
Обычные enum — исключение среди рассмотренных конструкций: они создают JS-объект.

**Явная типизация:** `const age: number = 25`.
**Вывод типов:** `const user = { age: 25 }` — у `user.age` выводится `number`.
Отсутствие аннотации не означает отсутствие проверки.

**Структурная совместимость:** важны доступные свойства и их типы, а не имя
интерфейса. Объект с `name` и `age` можно передать туда, где требуется `name`.

**Типы как множества:** `'green'` — одно значение, `string` — все строки,
`A | B` — значения хотя бы одного типа, `A & B` — значения, подходящие обоим.
`never` — пустое множество; `unknown` принимает любые значения. У `any` особые
правила: не пытайся объяснять его как обычный безопасный тип-множество.

**Осторожность с обходом проверок:** `any`, `as Type`, `value!` и `@ts-ignore`
могут скрыть проблему. Это не абсолютный запрет: важно обосновать гарантию,
которую компилятор не видит. Обычная проверка предпочтительнее утверждения наугад.
`as const` сохраняет литералы; это не произвольное обещание о внешних данных.
`satisfies` проверяет совместимость при компиляции, но не во время выполнения.

## Что закрепить в первую очередь

1. `(arg: Input): Output` — отдельно тип входа и тип результата функции.
2. Generic сохраняет связь типов; он не проверяет данные во время выполнения.
3. `as number` не равен `Number(value)`; `!` не равен проверке на undefined.
4. `typeof value` в типах, `keyof T` и `T[K]`: тип объекта -> ключ -> тип поля.
5. `?.` для допустимого отсутствия, `??` для запасного значения;
   явная проверка/ошибка, когда отсутствие недопустимо.
6. Чтение кортежа, union литералов, объекта `as const` и обычного enum.

Тонкости const enum, сложные условные типы и обобщённые обёртки Object.keys
пока достаточно узнавать. Не требуется воспроизводить их по памяти.

## Самопроверка без запуска

Объясни результат и причину:

```ts
const value = '42' as unknown as number;
// Что вернёт typeof value при выполнении? Превратилось ли значение в число?

const score = 0;
// Чем отличаются score || 10 и score ?? 10?

const user = { name: 'Vasya', age: 25 };
type Keys = keyof typeof user;
type Age = (typeof user)['age'];
// Какие типы получились в Keys и Age?
```

## Одно упражнение перед следующим фрагментом видео

Создай `AccountSettings`: обязательные `name: string` и `notifications: boolean`,
необязательное `address?: { city: string }`.

1. Создай объект с `satisfies AccountSettings`.
2. Напиши `getCity(settings: AccountSettings): string`: город либо «Не указан».
3. Напиши `getSetting<T, K extends keyof T>(obj: T, key: K): T[K]`.
4. Прочитай notifications и объясни тип результата. Проверь, что неизвестный
   ключ отвергается компилятором (ошибочный вызов потом закомментируй).

Без any, as Type и non-null assertion. Проверь отсутствие адреса и значение
notifications: false. Решение пиши сам в `Задачи.ts`.

Если можешь объяснить примеры и сделать упражнение с небольшой сверкой синтаксиса,
иди дальше по видео. Возвращайся к базе по мере новых задач; идеальное запоминание
всех конструкций не требуется. Если решаешь только копированием, сначала повтори
конкретную непонятную связь типов, а не весь курс заново.
